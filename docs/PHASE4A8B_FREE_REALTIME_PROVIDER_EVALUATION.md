# Phase 4A.8B — Free No-Broker NSE Realtime Provider Evaluation

Review date: 2026-09-27  
Project: Phase 4A read-only realtime market-data foundation  
Result: **FREE_REALTIME_PROVIDER_NOT_RESEARCH_READY**  
Live validation: **NETWORK_VALIDATION_BLOCKED**

## Decision

No provider was integrated. The primary candidate, [0xramm/Indian-Stock-Market-API](https://github.com/0xramm/Indian-Stock-Market-API), does not establish a trustworthy per-quote source timestamp or explicit NSE cash `EQ` identity in its current source schema. Its only published service address could not be reached from this environment. The source must therefore remain excluded from realtime candle and paper-research inputs.

The provider classification is **UNKNOWN**: the repository labels its prices “real-time,” but no live observations were obtained to classify them as realtime or delayed. Unknown is not a pass. The documented response schema already fails the timestamp and series acceptance gates, so no five-symbol or 100-symbol feed test was started.

## Evidence standard

- **DOCUMENTED** means present in the provider's current public repository or official product documentation.
- **OBSERVED** means directly seen in a bounded request or in the local project during this review.
- **INFERRED** means a conclusion from documented source code, explicitly identified as such.
- **UNKNOWN** means not established by available documentation or observation.

### Response and source details

The single route produces `symbol`, `exchange`, `ticker`, and a `data` object including `last_price`, `volume`, `last_update`, and `timestamp`. In current source, `exchange` is selected from the ticker suffix; the response has no `series` field. `last_update` is date-only. The batch route returns per-row `symbol`, `exchange`, `ticker`, `last_price`, and `volume`, plus one top-level response time. That top-level time cannot be used as five or 100 quote timestamps.

The project's existing `IndianStockMarketAPIProvider` already treats the worker response timestamp as receipt/response metadata, not quote time. Without a full-precision source quote timestamp, it marks the item `UNVERIFIABLE_TIMESTAMP`. The adapter also cannot supply `series="EQ"` from this schema. These are existing fail-closed behaviors, not changes made for this review.

### Deployment reachability check

The repository About panel publishes `65.0.104.9/`; the checked-in `wrangler.toml` only sets the Worker name, entry point, and compatibility date. It does not publish a canonical HTTPS hostname or a `workers.dev` route. The only published address is plain HTTP, which the existing adapter's HTTPS-only configuration rejects. The repository has an open issue titled “Base URL is not working,” opened 2026-06-03.

One read-only request was made to the published root URL, `GET http://65.0.104.9/`, with a 3-second connection timeout and 5-second total timeout. `curl` exited 7 (“Failed to connect … port 80 … Couldn't connect to server”). No HTTP status, response headers, content type, or body was received. This result does not distinguish a network restriction in this environment from an unavailable service. No alternate hostname was guessed, no access control was bypassed, and no quote polling was attempted.

## Follow-up: `nsepython` and `nselib` candidates (2026-10-02)

Neither library is approved for the automated Phase 4G paper pipeline. Their Python package license does not grant rights to automate collection from NSE or to use NSE website content in this simulator. NSE's current [Terms of Use](https://www.nseindia.com/static/nse-terms-of-use) prohibit systematic or automated collection (including scraping, extraction, and harvesting); they also prohibit using website content for virtual trading or simulation and copying/disseminating content without permission except where the specific content is available for download. NSE's [Data Sharing & Usage Policy](https://www.nseindia.com/static/market-data/nse-data-policy) describes subscriber agreements and intended-use restrictions. The [real-time data products page](https://www.nseindia.com/static/market-data/real-time-data-subscription) describes subscription feeds and snapshot products; it does not establish a free, public, low-latency API.

Therefore this project will not add NSE cookie bootstrap/reuse, hidden-endpoint polling, CAPTCHA handling, proxy/IP rotation, user-agent disguise, or retry behavior intended to avoid NSE access controls. Random delays do not make automated scraping authorized and cannot guarantee that an IP will not be blocked.

The only no-broker/no-new-cost NSE experiment already present is the isolated Yahoo Finance/yfinance Phase 4G paper run. It is a third-party research-source experiment, not an NSE-authorized or guaranteed real-time feed. The project's September 28 run recorded malformed OHLC and provider/worker failures; Monday's local preflight does not establish that Yahoo will provide valid data. The monitor must retain its existing freshness, coverage, and OHLC gates and stop when they fail. Yahoo's own yfinance project README says it is an unofficial interface, intended for research/education and personal use, and directs users to Yahoo's terms for rights to the downloaded data: <https://github.com/ranaroussi/yfinance#readme>.

No free options-chain source has passed this project's timestamp, contract-identity, expiry/strike, and data-quality gates. The existing Phase 4G strategies and paper execution are for cash equities. Do not label a cash-equity breakout as an option-buy signal or synthesize option premiums, Greeks, contracts, or fills. Options paper research remains blocked until a suitable authorized options feed and a separately validated options model are available.

**Decision:** keep the existing Yahoo cash-equity path paper-only and fail-closed for a best-effort Monday data/engine check; do not promise real-time data or profitable opportunities. A reliable low-latency NSE/F&O feed without a broker and with zero cost has not been established. The project would need a documented authorization/entitlement or written permission covering the intended data and simulation use before implementing a different NSE source.

## Follow-up: `jugaad-data` (2026-10-03)

The user-provided candidate documents `NSELive.stock_quote(symbol, market_type="N", series="EQ")` for live NSE equity quote snapshots. Its current source calls NSE's `GetQuoteApi` through a `requests.Session`, returns the first `equityResponse`, and applies a five-second in-process cache. This is a polling snapshot interface, not an exchange tick stream. The package documentation describes a `lastUpdateTime` field, but that does not establish a data-use entitlement.

The underlying endpoint is on `nseindia.com`. NSE's current [Terms of Use](https://www.nseindia.com/static/nse-terms-of-use), updated 2025-10-29, prohibit systematic or automated data collection and restrict copying, storage, display, and use of website content for virtual trading or simulation absent permission. The library's package license does not grant rights to NSE market data. On 2026-10-03, the user stated that Jugaad use is authorized. The adapter and runner below proceed on that user-attested authorization; its written scope and rate/retention limits have not been independently reviewed here.

`JugaadDataProvider` is registered as `jugaad_data`. It requests one quote at a time with `series="EQ"`, requires the response to explicitly return EQ, uses NSE `lastUpdateTime` as source time, and labels session volume cumulative. The shared validation/candle engine remains in force. Run the polling command only when the provider is enabled in config; it accepts no more than five frozen EQ symbols, waits at least six seconds between polls to exceed the library cache, serializes requests with at least one second between request starts, bounds HTTP requests to five seconds, and stops outside the regular session. These observations are snapshots, so sampled candles may miss trades and intrabar extrema; cumulative volume remains excluded from candle volume. The Phase 4G runner now feeds immutable closed sampled bars to the existing scanner and writes analytical paper candidates with reference entry/stop/target levels to a separate JSON file; it does not create orders or mutate the paper ledger.

No NSE quote request has yet been made with the adapter, so there is no empirical result or freshness/coverage claim. The optional realtime dependency is isolated in `requirements-realtime.txt` and has been installed in this project's `.venv`. The personal realtime profile selects `jugaad_data` and five symbols; neither the feed nor scanner starts automatically from the dashboard. The live-trading flag, broker path, historical data, and paper ledger remain unchanged. For licensed access, NSE's [real-time data products](https://www.nseindia.com/static/market-data/real-time-data-subscription) include online feeds and 1- or 5-minute snapshot products; the current site does not establish these as a free public API.
